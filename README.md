# DELIS CRM

CRM для дистрибуции бытовой и автохимии: заказы, склад, клиенты, агенты,
финансы, доставка, рассылки и портал агента.

Стек: **Next.js 16** (App Router, Turbopack) · **React 19** · **PostgreSQL** ·
**Drizzle ORM** · Tailwind CSS 4.

## Быстрый старт

```bash
npm install
cp .env.example .env      # укажите DATABASE_URL
npm run dev
```

Приложение поднимется на http://localhost:3000.

При первом запуске схема БД создаётся автоматически (миграции применяются
на старте), после чего создаётся минимальный базовый набор: аккаунт владельца,
справочник категорий и строки интеграций. Операционные данные (товары, заказы,
клиенты, агенты) **не заливаются** — они наполняются вручную через разделы CRM.

**Вход по умолчанию:** логин `owner`, пароль `delis2026`

Демо-сотрудники автоматически **не создаются** — аккаунты для ролей
`admin`, `manager`, `warehouse`, `support`, `agent` и др. добавляются вручную
в разделе «Пользователи» (доступен Owner/Admin). Матрица доступов каждой роли
описана в `src/shared/config/nav.ts`.

Список ролей и их доступы:

| Логин | Роль | Доступ |
|---|---|---|
| `owner` | Owner | всё |
| `admin` | Admin | всё |
| `manager` | Manager | заказы, товары, склад, клиенты, маркетинг |
| `warehouse` | Warehouse | товары, склад, поставщики, возвраты, доставка |
| `support` | Support | чат, клиенты, заказы, возвраты |
| `agent` | Agent | портал агента, заказы, клиенты, чат |

Финансы (`/finance`, `/pnl`) и управление аккаунтами (`/users`) доступны
только Owner и Admin. Смените пароль владельца перед выкладкой на боевой
сервер (переменной `OWNER_PASSWORD`).

## Переменные окружения

| Переменная       | Обязательна | Назначение                                            |
| ---------------- | ----------- | ----------------------------------------------------- |
| `DATABASE_URL`   | да          | Строка подключения к PostgreSQL                        |
| `OWNER_PASSWORD` | нет         | Пароль владельца при первичном сиде (по умолч. `delis2026`) |
| `UPLOAD_DIR`     | нет         | Каталог загрузок (по умолч. `public/uploads`)          |
| `UPLOAD_PUBLIC_PREFIX` | нет   | Публичный префикс URL файлов (по умолч. `/uploads`)    |
| `TRUST_PROXY`    | нет         | `1`, если приложение за прокси, перезаписывающим `x-forwarded-for` |

## Права доступа

Матрица ролей одна на всё приложение — `ROLE_ACCESS` в
`src/shared/config/nav.ts`. По ней проверяются три уровня:

- **страницы** — общей проверкой в layout группы `(crm)`;
- **действия** `/api/manage` — таблицей `ACTION_POLICY`;
- **REST-маршруты** — хелпером `requireApiAccess` из `src/server/apiGuard.ts`.

Новый маршрут обязан вызывать `requireApiAccess("/раздел")`: проверки только
на факт входа недостаточно, иначе раздел, закрытый в меню, останется
доступен обычным запросом к API. Тест `tests/api-access.test.ts` следит
за этим статически.

Роль `agent` дополнительно ограничена своими данными: диалоги и портал
агента связываются с аккаунтом по email.

Сквозные каналы тоже закрыты: печатные формы (`/print/*`) требуют доступ
к разделу заказов, а глобальный поиск фильтрует выдачу по роли — иначе
через него видны клиенты и суммы заказов из закрытых разделов.

## Сессии

Вход создаёт сессию на 30 дней; cookie `httpOnly`, `sameSite=lax`, а в
production ещё и `secure`. Смена пароля или логина завершает все остальные
сессии пользователя (текущая вкладка остаётся), админский сброс пароля и
удаление аккаунта — все. Истёкшие сессии удаляются при старте приложения.

## Двухфакторная авторизация

Owner/Admin включает 2FA сотруднику в разделе «Пользователи»: система
генерирует секрет, показывает QR-код (Google Authenticator, Authy,
1Password), и защита включается только после подтверждения кодом из
приложения — чтобы не запереть аккаунт, который не настроен. TOTP — RFC 6238
(HMAC-SHA1), реализация в `src/server/totp.ts` без внешних зависимостей.

При входе после верного пароля запрашивается 6-значный код. Секрет хранится
в колонке `users.otp_secret` (миграция `0004_two_factor`). Перебор кода
ограничен теми же лимитами, что и перебор пароля.

## Live-уведомления

Лента в колокольчике и тосты обновляются в реальном времени через
Server-Sent Events (`/api/events`): новые записи журнала действий приходят
без перезагрузки страницы. Выбран SSE, а не WebSocket, — это обычный route
handler Next.js, который работает на Vercel без отдельного сервера.

## Push-уведомления (Web Push)

Сотрудник включает браузерные уведомления в «Настройках»: браузер
запрашивает разрешение, подписка сохраняется в таблице `push_subscriptions`,
и новые заказы приходят push-уведомлением даже при закрытой вкладке.

Требует VAPID-ключей:

```bash
npm run vapid:generate   # выведет VAPID_PUBLIC_KEY и VAPID_PRIVATE_KEY
```

Положите их в переменные окружения `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY`
и `VAPID_SUBJECT` (ключи должны быть стабильны между деплоями).
Шифрование полезной нагрузки и подпись VAPID — библиотека `web-push`
(каноническая реализация протокола). Обработчики `push`/`notificationclick`
— в `public/sw.js`.

## Миграции БД

Источник правды — `src/db/schema.ts`. После изменения схемы:

```bash
npm run db:generate   # создаст SQL-файл в drizzle/
```

Полученные файлы **обязательно коммитятся**. Применяются они автоматически
при старте приложения, либо вручную через `npm run db:migrate`.

### Базы, созданные старой версией

Раньше таблицы создавались «сырым» DDL в рантайме, без журнала миграций.
Для таких баз предусмотрен baseline: если таблицы уже существуют, а журнал
пуст, первая миграция помечается как применённая, не выполняясь повторно.
Данные при этом не теряются.

## Загрузка файлов

В БД пишется только короткий URL, а сами байты хранит драйвер
`StorageDriver` (`src/server/storage.ts`). Приём ограничен белым списком
MIME (изображения, видео, PDF), тип проверяется по сигнатуре файла, а не
по заголовку от клиента.

Два драйвера на выбор (переменная `STORAGE_DRIVER`):

- **`local`** (по умолчанию) — файлы на диске в `UPLOAD_DIR`
  (`public/uploads`), Next отдаёт их статикой.
- **`s3`** — объектное хранилище (AWS S3, Cloudflare R2, MinIO,
  DigitalOcean Spaces и др.) через `src/server/s3.ts`. Подпись запросов —
  AWS Signature V4 без внешних SDK (`src/server/s3sign.ts`).

Для `s3` задайте `S3_ENDPOINT`, `S3_BUCKET`, `S3_ACCESS_KEY_ID`,
`S3_SECRET_ACCESS_KEY` и, при необходимости, `S3_REGION` (для R2 — `auto`),
`S3_FORCE_PATH_STYLE` и `S3_PUBLIC_BASE_URL`. Полный список — в
`.env.example`.

> На платформах с эфемерной ФС (Vercel и т.п.) задайте `UPLOAD_DIR` с
> постоянным томом либо переключитесь на `STORAGE_DRIVER=s3`.

## Деплой на Vercel

Приложение — обычный Next.js App Router и готово к Vercel без доп. сервера
(SSE сделан через route handler). Для запуска на проде настройте:

### 1. База данных
Vercel не хранит вашу PostgreSQL — нужна внешняя БД (Neon, Supabase,
Vercel Postgres и т.п.). Создайте БД и пропишите строку подключения:

```html
DATABASE_URL=postgresql://user:pass@host:5432/dbname
```

Миграции применяются автоматически при первом старте, данные (owner,
категории, интеграции) создаются сами.

### 2. Хранилище файлов
Файловая система на Vercel эфемерная — файлы пропадают при передеплое.
Выберите один из двух вариантов:

- **`STORAGE_DRIVER=s3`** (рекомендуется) — Cloudflare R2 / AWS S3 / MinIO.
  Задайте `S3_ENDPOINT`, `S3_BUCKET`, `S3_ACCESS_KEY_ID`,
  `S3_SECRET_ACCESS_KEY`, `S3_FORCE_PATH_STYLE=true` (для R2 — `S3_REGION=auto`).
- **постоянный том** — если подключите сборку с диском.

### 3. Push-уведомления (Web Push)
Сгенерируйте VAPID-ключи и пропишите в Environment Variables:

```bash
npm run vapid:generate
```

```html
VAPID_PUBLIC_KEY=...
VAPID_PRIVATE_KEY=...
VAPID_SUBJECT=mailto:you@example.com
```

### 4. Минимум переменных на проде

| Переменная       | Зачем |
| ---------------- | ----- |
| `DATABASE_URL`   | подключение к БД |
| `OWNER_PASSWORD` | пароль владельца (обязательно сменить) |
| `STORAGE_DRIVER` | `s3` или пусто (local) |
| `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY`, `VAPID_SUBJECT` | push |
| `TRUST_PROXY`    | `1`, если Vercel (перезаписывает x-forwarded-for) |

### Деплой
Импортируйте репозиторий в Vercel или используйте CLI:

```bash
npm i -g vercel
vercel        # первичный деплой (создаёт проект и env)
vercel --prod # прод-деплой
```

После деплоя смените `/api/health`-проверки и войдите как `owner`.

> SSE-лента (`/api/events`) на Vercel ограничена `maxDuration` функции
> (60 с на Hobby). `EventSource` на клиенте при обрыве сам переподключается
> и по `Last-Event-ID` докачивает пропущенное — это ожидаемое поведение,
> «разрыв» соединения не выглядит как ошибка для пользователя.

## Тесты

```bash
npm test
```

Покрыты хеширование паролей, права ролей, валидация загрузок (включая
подделку MIME), файловое хранилище, экспорт XLSX, права на действия API,
ограничение попыток входа и применимость миграций.

Тестам, работающим с БД, нужен `DATABASE_URL`: они создают временные базы
и удаляют их за собой. Без переменной такие тесты пропускаются.

